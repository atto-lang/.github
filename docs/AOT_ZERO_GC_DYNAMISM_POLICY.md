# AttoLang organization policy: AOT and controlled dynamism

**Architectural review directive, not a declaration of compiler support.** Use [atto-spec](https://github.com/atto-lang/atto-spec) for current language semantics, [atto-target-profiles](https://github.com/atto-lang/atto-target-profiles) for target restrictions, [atto-platform-conformance](https://github.com/atto-lang/atto-platform-conformance) for executed proof, and the [backend capability matrix](https://github.com/atto-lang/.github/pull/10) for design responsibilities. The old Oreslang-language and organization PRs are migration context, not current normative authority.

## Mandatory author/reviewer checklist

1. Name the code profile: interpreter/JIT, hybrid, host-only AOT, **sealed full guest AOT**, or separately governed precompiled-module AOT. Sealed AOT must execute only precompiled, verified and authenticated guest code: forbid guest eval, runtime source compilation, arbitrary class/method injection, unbounded reflection, monkey-patching, unknown proxy types, and silent interpreter/JIT fallback. Hot-loaded precompiled modules may be admitted by an authenticated, capability-checked manifest and safe ABI/lifecycle rules; do not conflate these with runtime guest compilation. Fail before executable IR when unsupported.
2. Preserve expressive features via compiler-known finite metadata: virtual methods, interfaces, typeclasses, generics, hygienic macros, statically lowered closures/async continuations, and generated proxy forwarders for a known class/interface. Static class-level methods are not magically instance methods; no privacy/effect/capability escalation.
3. Name the memory claim: managed-host, **zero guest tracing-GC**, or independently demonstrated **process zero-GC**. Java/.NET/JavaScript hosts may remain GC-managed despite AOT/trampolines/off-heap actor arenas. Wasm guest linear memory does not remove browser JS GC.
4. Check current Atto ownership operations (`borrow!`/`take!`/`share!`/`copy!`/`copy!!`/`pin!`/`drop!`, with implicit shared borrowing where valid), actor heaps, continuations, closure captures, reference cycles, long-lived actor reclamation, bounded quotas/OOM, cancellation and generation-fenced exactly-once cleanup. Channels/pub-sub carry Sendable data, never arbitrary functions/closures/foreign pointers.
5. Preserve **current** approved Atto language semantics, including contextual `^` return forms and supported bitwise operators; do not revive historical blanket exclusions for `%`, `^`, `^^` or other tokens. Distinguish equality from identity, function pipelines from actor pipelines, and explicit Option/Result/Future effects. Unsupported frontend syntax must fail closed; use canonical `.atto` for new guest code.
6. Provide positive and **negative-before-IR** compiler tests for dynamic feature boundaries (eval, unknown proxy, reflection escalation, borrow escape across await, closure transport, cycles, hidden fallback), plus real runtime cancellation/allocator stress. For AOT/zero-GC claims, capture exact source/compiler/fixture SHAs, generated artifact hash and actual stepful guest execution and GC instrumentation. `steps=[]` or `steps=null` is NOT_EXECUTED.

## AOT/JIT instrumentation, tenant security and fault containment

JIT optimization and AOT binaries must preserve shared language semantics and a typed instrumentation/event ABI. Sealed guest AOT may use pre-emitted probes, protected safe points and runtime enable masks; this is not permission for arbitrary executable patching or host-object introspection. Graal Native Image and .NET NativeAOT are **host AOT**, not automatic guest AOT; host-managed GC may remain.

For mutually untrusted tenants in one OS process, require an independently verified memory/control-flow safety boundary. Separate actor heaps, stacks, host Workers and POSIX signal handlers alone are insufficient to promise survival of native SIGSEGV or stack overflow. If the native model is not proven, require a stronger process-isolated fallback.

For the strict untrusted guest profile, forbid direct filesystem/environment/subprocess/FFI/raw descriptors and uncontrolled OS I/O; allow only brokered network I/O through revocable, generation-fenced tenant-bound socket capabilities and separately authorized connect/bind/accept/read/write rights. Deno-style flag parsing, including flags-2-env where applicable, is not itself the enforcement boundary.

This document does not grant permission to mirror private source or bypass reviews, required checks, existing Rust-only tooling, sandbox capabilities or deployment approvals. Brand and repository migration do not establish backend parity.
