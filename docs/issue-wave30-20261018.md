# Private-safe reusable verification workflow contract — draft 2026-10-18

Issue #6: reusable, fail-closed workflows for TypeSpec ↔ JSON Schema peer-authority comparison, WIT parser conformance and proof receipts.

## Trigger and authorization
- A shared workflow should be `workflow_call` only: no secret-bearing `pull_request_target`, untrusted `issue_comment` code, or ambient write token. Default `permissions: contents: read`.
- Check out only the triggering repository's immutable head SHA; if a verified private cross-org CI carrier is explicitly approved, prove source Git tree SHA equality before execution. Never export private source to public repositories.
- Pin all action dependencies by full immutable SHA and language toolchains by lockfile/digest; prohibit arbitrary curl-to-shell.
- Concurrency isolation and artifact retention must be explicit. Avoid sharing cache or artifacts across unrelated private repositories.

## Required jobs
1. Validate lockfile and SBOM against source/toolchain digests.
2. Build TypeSpec JSON Schema witness and compare **in memory** with independently maintained Draft 2020-12 schema; execute positive and negative drift mutants.
3. Parse WIT using pinned grammar and separately validate ABI capability projections.
4. Run bounded formal proof suite with digested inputs and emit signed/digest-bound verdicts (no unexecuted job counted as proof).
5. For any backend claim, compile and execute actual guest source on matching backend with immutable tool/version receipt.
6. Refuse release if jobs have zero executed steps or if branch protection is absent from required source.

**Status:** security-reviewed workflow acceptance gate only; no workflow has been enabled here, avoiding an unreviewed path to private code publication.
